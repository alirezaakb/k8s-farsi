# جزوه‌ی کوبرنتیز

سایت جزوه‌ی آموزشی فارسی کوبرنتیز، ساخته‌شده با React و Vite و منتشرشده روی GitHub Pages: صفحه‌ی اصلی (نقشه‌ی راه، برنامه‌ی مطالعه، مسیر سریع)، یک صفحه برای هر فصل و صفحه‌ی منابع. جستجو در همه‌ی فصل‌ها با `/` یا `Ctrl+K`.

## ویرایش متن

متن جزوه فایل‌های HTML ساده‌ی پوشه‌ی `content/` است:

| فایل | محتوا |
|---|---|
| `content/ch1.html` … `ch17.html` | هر فصل (یک `<section class="ch" id="chN">`) |
| `content/home.html` | جلد، نقشه‌ی راه، برنامه‌ی مطالعه، مسیر سریع |
| `content/sources.html` | منابع |
| `content/book.json` | نام جزوه و عنوان بخش‌ها (بخش اول، دوم، …) |

```bash
npm install     # فقط بار اول
npm run dev     # http://localhost:5173
```

فایل را در هر ویرایشگر باز کنید و ذخیره کنید؛ صفحه خودکار دوباره بارگذاری می‌شود.

نکته‌ها:
- **لینک به هر جای جزوه** فقط `href="#id"` است؛ id هر عنوان یا بخش، در هر فصلی که باشد. سایت خودش آدرس درست را می‌گذارد.
- **تصویر** را در `public/img/` بگذارید و در متن `src="img/نام-فایل.svg"` بنویسید.
- **فصل تازه:** فایل `content/ch18.html` را با همان ساختار بسازید (`ch-num` و `h2`). فهرست و دکمه‌ی قبلی/بعدی خودکار ساخته می‌شود. اگر فصل شروع بخش تازه‌ای است، عنوانش را در `book.json` اضافه کنید.
- **عنوان‌های سطح ۳ (`<h3 id="...">`)** در فهرست کناری فصل نشان داده می‌شوند. هر h3 یک id یکتا لازم دارد.
- هایلایت‌های ذخیره‌شده با متن اطرافشان پیدا می‌شوند، پس ویرایش‌های کوچک آن‌ها را از بین نمی‌برد. اگر متنی که هایلایت شده تغییر کند، در پنل یادداشت‌ها «جای این متن پیدا نشد» نشان داده می‌شود.

## ویرایش متن هنگام خواندن

می‌توانید همان‌طور که فصل را می‌خوانید، متن را روی خود صفحه تغییر دهید و با یک دکمه در GitHub ثبت کنید.

1. **روشن‌کردن روی یک دستگاه:** یک بار آدرس سایت را با `?edit` باز کنید (مثلاً `https://…/k8s-farsi/ch3?edit`). دکمه‌ی «ویرایش متن» فقط روی همین دستگاه ظاهر می‌شود و خوانندگان دیگر آن را نمی‌بینند.
2. **ویرایش:** دکمه‌ی «ویرایش متن» را بزنید و روی متن کلیک کنید. هر تغییر خودکار در مرورگر نگه‌داری می‌شود (حتی اگر به فصل دیگر بروید یا صفحه را ببندید). چسباندن متن فقط به‌صورت متن ساده انجام می‌شود. کد و تصویر و دکمه‌ها قابل ویرایش نیستند.
3. **ثابت‌کردن:** «ثبت در GitHub» فایل همان صفحه (`content/chN.html`) را commit می‌کند و سایت خودکار یکی دو دقیقه بعد برای همه به‌روز می‌شود. تا آن موقع، متن ثبت‌شده در همین مرورگر هم دیده می‌شود. «دور انداختن» ویرایش‌های ثبت‌نشده را برمی‌گرداند.
4. **توکن (یک بار):** در GitHub بروید به Settings ← Developer settings ← Personal access tokens ← **Fine-grained tokens**، فقط مخزن `k8s-farsi` را انتخاب کنید و دسترسی **Contents: Read and write** بدهید. توکن را در نوار ویرایش (دکمه‌ی «توکن») بنویسید. فقط در همان مرورگر نگه‌داری می‌شود.

**غیرفعال‌کردن:** در `content/book.json` مقدار `editing.enabled` را `false` کنید و push کنید؛ کد ویرایش دیگر در سایت نیست. برای خاموش‌کردن فقط روی یک دستگاه، دکمه‌ی «خاموش‌کردن» در نوار ویرایش یا `?edit=0`.

نکته‌ها:
- ثبت، کل فایل صفحه را می‌نویسد. اگر فایل در GitHub بعد از باز کردن صفحه عوض شده باشد، قبل از جایگزین‌کردن از شما می‌پرسد.
- فایل‌های `content/` باید به همان شکلی باشند که مرورگر آن‌ها را می‌نویسد، وگرنه commit خط‌های بیشتری از تغییر شما را عوض می‌کند. اگر فایلی را دستی ویرایش کردید، یک بار `npm run canonicalize` را اجرا کنید.
- ویرایش با `npm run dev` روی کامپیوتر هم کار می‌کند، ولی ثبت در GitHub انجام می‌شود، نه نوشتن در فایل محلی؛ بعدش `git pull` بزنید.

## بخش تعاملی با React

داخل هر فصل می‌توان یک کامپوننت React گذاشت:

```html
<div data-widget="Quiz" data-props='{"question": "…"}'></div>
```

کامپوننت را در `src/widgets/` بسازید و در `src/widgets/index.js` با همان نام ثبت کنید. جاهای دیگر سایت (فهرست، جستجو، تنظیمات مطالعه) هم کامپوننت‌های React در `src/components/` هستند.

## ساخت و انتشار

```bash
npm run build      # ساخت سایت در dist/ و فهرست جستجو
npm run preview    # دیدن نسخه‌ی ساخته‌شده (جستجو فقط در این حالت کار می‌کند)
```

انتشار خودکار است: هر push روی `main` سایت را با `.github/workflows/pages.yml` می‌سازد و منتشر می‌کند. یک بار در مخزن **Settings ← Pages ← Source** را روی **GitHub Actions** بگذارید.

## ساختار

| مسیر | کار |
|---|---|
| `content/` | متن جزوه |
| `public/img/` | تصویرها |
| `src/` | برنامه‌ی React: `App.jsx` (مسیرها)، `components/` (فهرست، جستجو، تنظیمات)، `lib/` |
| `src/legacy/notes.js` | هایلایت و یادداشت (کد قدیمی غیر React که به همین صفحه وصل می‌شود) |
| `scripts/` | خواندن فهرست فصل‌ها از `content/` و ساخت فهرست جستجو بعد از build |
| `tools/split.py`، `source/jozve.html` | فقط برای تبدیل اولیه‌ی فایل تک‌صفحه‌ای به `content/`؛ بعد از آن لازم نیستند |

## یادداشت‌ها و تنظیمات

هایلایت‌ها، یادداشت‌ها، تیک روزهای برنامه، تم و تنظیمات مطالعه در `localStorage` مرورگر ذخیره می‌شوند. چون آدرس سایت با فایل قبلی فرق دارد، داده‌های قبلی خودکار منتقل نمی‌شوند. از نسخه‌ی قبلی «پشتیبان JSON» بگیرید و در سایت جدید با «بازیابی از فایل JSON» وارد کنید.
